# Practical validation policy

本文件拥有普通制作的技术校验边界与重复检查规则。命令见 sp-deck 的 main-session-production.md；研究证据规则由 research-workflow.md 所有。

## 同一技术判定

run、complete、quality_gate.py、delivery_check.py、run_gates.py、pptx_tool.py 的 gate-all/content-qa/qa-manifest 及历史版本 CLI 使用 shared/artifact_validation.py。历史版本参数兼容调用，不选择更严格的旧验收链。历史模块的分析函数只供旧记录读取和显式诊断，不是普通交付依赖。

实际文件损坏、明确要求的事实或备注缺失、素材契约错误及源稿保护仍需处理。制作前确认 Production Summary。作者实际阅读材料、核对关键结论和查看最终页面；工具不自动证明语义或美观。

普通交付不要求 Spec lock、Art Direction、五项视觉评分、固定字号/标题正文比例、口播字速阈值、逐页 checked、固定修复轮数或串联报告哈希。可选观察只记录有发现的页面即可。空评分不表示质量不合格，填满也不证明验收。

## 事实与可见内容

must_show_exact 仅承载用户明确要求保留的字样、引文或记号。作者自写的规划句、标签和研究流水信息不自动升级为逐字要求。一般结论用 must_convey，确需机器检查的指标可用 fact_bindings；不冻结整句文案。

回读包含文本、表格和原生图表实际显示的标签；隐藏缓存不算上屏内容。先应用图表显示格式再核对；同图标题或对应坐标轴的单位可用于其数据标签，不为通过回读而复制一段数字到正文。无法可靠识别的显示格式需实际看图核验，不能声称隐藏数据已显示。

同页唯一且明确的年份可作指标共同背景；混合年份保留局部绑定。指标名称、数值和单位须在逻辑或空间关联的区域成立，不能任意拼接文本框。错地区、错年份、错单位、否定和比较句不能伪装成直接事实。

验收要求来自用户任务、提供材料和确认摘要。“大型化趋势”不自动意味着必须给出海上/陆上特定 MW 分布；建议不能自行变成核心缺口。新增比较、主导份额和因果结论须有来源。换词或调整语序不能汇报成已纠正事实。

## 只重查相关变化

未变的技术输入复用校验，未变的作者源码复用构建；complete 使用当前实际文件与输入，变化使相应缓存失效。不要求作者手工维护哈希链，不为打印摘要再次 run。哈希只用于缓存失效及保留原件，不证明研究可信度或真实看图。

几何预测、措辞、留白和配色建议只是线索。先判断实际问题，不设清零 warning 目标，不为建议删证据、缩字或堆正文。已通过的检查只在相关内容变化、新错误或疑点未解决时重做。

首次完成后查看全部最终页。修复后查看变化页；公共字体、母版、整体布局或叙事变化时扩大范围。仅备注变化仍核对备注事实，但复用视觉相同的渲染，无需全套重看。检查范围和未验证条件如实表述，不以 checked 代替操作。

失败读取本次返回的 last-build-report.json，含本次 attempt、输入和错误。上次成功报告不描述本次失败；status 优先显示最近失败。按当前诊断改相关输入，不反复构建来等待变绿。

局部 preview 只渲染所选页，不加载其他未完成模块、不覆盖完整成果或生产 manifest、不表示 complete。最终仍需完整生成、核对和渲染。

## 收口与通知

后台完成事件和正常交接可能只是同一结果的两次通知。选当前权威状态，不反复轮询、等待可选 hook 回执或因第二次通知重新研究。成果内容未变时继续下游；明确事实错误、缺少用户要求或实质变更才重新打开。增强建议仍是建议；再查一次更放心不能自行成为新标准。
