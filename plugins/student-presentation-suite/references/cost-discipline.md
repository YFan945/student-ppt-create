# Context And Cost Discipline

PPTX 创建和编辑由主会话完成，不创建页面/评审子代理、Packet、分片、校准或回执。工具实现确定性工作，不用模型反复推进状态。

- 同一批独立素材、文件和命令合并处理；先看素材再决定构图。
- 页面拆为小模块，修改受影响页即可；不反复重写整套生成器。
- `plan` 一次准备源码；`run` 一次构建、检查、渲染；看图修改后再 `run`；`complete` 导出。
- `run` 的首次尝试加最多 3 轮修复是默认预算，明确的任务预算优先，工具上限 6。每轮批量处理当前问题，不按检查类别分别修。
- 不生成无消费方的设计、校准或评分 JSON；报告和状态由工具维护。
- 先读总览了解节奏，再检查单页的真实可读性；有变化才重新看图，不累计重复图片。
- 有明确错误就修错误，不把接口摸索、回执排障或重复调用当成生产进度。
- 外部事实由 `sp-research` 的研究员检索；遵守其证据、检索预算和结束协议。图片权限与来源仍按 `image-sourcing.md`。
- 用会话统计记录模型请求数和工具次数；CLI 成本只是所配置后端的估算，不能视为实际账单。同 session 的累计值取最大值，不能相加。

普通任务不强制中途结束会话。长任务可写简短 checkpoint 后继续，保留事实与当前产物路径，无需重新注入整个 skill。
