# Golden sample — "AI 幻觉" coursework deck

A **reproducible showcase** of the v0.8 generation pipeline, not a unit test.
Its purpose is to make the visual ceiling inspectable: a real 9-slide deck whose
every design decision is traceable to Art Direction, a retrieved visual
reference and a selected composition candidate.

## What makes it a golden sample

- It is generated by the real gate scripts in the real order — no shortcuts.
- Every high-leverage slide has retrieval evidence, 2 composition candidates and
  a rendered wireframe, all hash-bound by the v0.8 visual generation gate.
- It reaches `delivery-report.json` `status: complete` through
  `pptx_delivery_check_v08.py --strict --visual-reviewed`.
- It declares `diagram-only` image sourcing, so it reproduces with **zero
  network access and zero external image services**.

## Reproduce

```bash
# from the plugin root, with dependencies installed
python examples/golden-sample/build.py                 # full chain + LibreOffice render
python examples/golden-sample/build.py --skip-render   # skip the render step
```

Generated artifacts land in `outputs/golden-sample/` (git-ignored):
the PPTX, `render/*.png` previews, speaker notes, and the full report chain
(package, asset-manifest, actual-content, visual-review, quality, delivery).

## Files

| Path | Role |
| --- | --- |
| `slide-spec.yaml` | Frozen 9-slide plan: roles, claims, evidence refs, visuals, notes, timing |
| `art-direction.yaml` | Deck-wide visual decisions and the high-leverage slide list |
| `deck.js` | Model-authored generator (10×5.625in canvas, suite helpers) |
| `tokens.json` | Resolved design tokens for `Academic Rigorous` plus a derived dark palette |
| `composition/composition-candidates-<n>.json` | 2 distinct silhouettes per high-leverage slide |
| `composition/references-slide-<n>.json` | Retrieved references (regenerated by `build.py`) |
| `composition/wireframes-<n>.pptx` | Rendered candidates (regenerated, git-ignored) |
| `image-sources.json` | Explicit image capability declaration (diagram-only) |
| `asset-manifest.json` | Per-slide visual record with provenance fields |
| `expected/visual-review.json` | Authored visual review; `build.py` binds it to the PPTX hash |
| `build.py` | Driver that runs the whole pipeline and the delivery gate |

## Pipeline order

```text
tokens -> art_direction_check
-> visual_reference_select (per high-leverage slide)
-> composition_candidate_check
-> composition_wireframe.js
-> pptx_visual_generation_gate_v08
-> deck.js -> PPTX
-> package validate -> asset-manifest validate -> actual-content readback
-> validate_slide_spec -> slide_spec_guard freeze/revise
-> build_support_outputs (speaker notes)
-> render (LibreOffice + Poppler)
-> visual-review bound to pptx_sha256
-> pptx_quality_gate_v071
-> pptx_delivery_check_v08 (complete)
```

## The visual system

The deck is deliberately **not** a stack of centred rounded boxes:

| Lever | How it is used |
| --- | --- |
| Background rhythm | Navy cover, light content pages, navy section divider, navy closing |
| Type scale | 40pt cover / 32pt page title / 26pt statement / 22pt body / 11pt caption, so hierarchy is visible instead of title≈body |
| Accent meaning | The accent colour marks one emphasised line, the recommended option, the big number and the conclusion node — never decoration |
| Page system | Accent eyebrow + 32pt title + accent rule on every content page, plus a hairline footer with section label and page number |
| Evidence rail motif | A 3pt accent rule plus caption marks sourced/constructed evidence (slide 6, cover, closing) |
| Charts | Hand-authored: no gridlines, one accent series, direct data labels, big-number takeaway read first |

## Design decisions worth reading

1. **Slide 4 is not three equal cards.** Three subordinate causes sit above connectors
   that converge on one dominant navy conclusion panel, because the argument is
   "many causes, one failure mode".
2. **Slide 6 uses typographic evidence instead of a placeholder image.** With no
   approved image provider, an empty frame or floating stock photo would be
   dishonest; a typeset fabricated citation is both honest and information-bearing.
3. **Slide 7 is hand-composed, not `addComparison`.** The deterministic helper
   produces equal cards, which contradicts the asymmetric-decision reference.
4. **Slide 8 is a path, not `addSummary`.** The recap traces the argument order and
   the conclusion node is filled accent and set larger.
5. **Slide 9 carries the source block.** Evidence closure requires the final page to
   resolve every `evidence_refs` entry.
6. **Emphasised lines are separate text boxes.** pptxgenjs writes invalid OOXML
   (`a:pPr` in the wrong position) for rich-text arrays of two or more runs, so
   accent-in-title is achieved by stacking single-run text boxes instead.

## Known limitations (deliberate)

- Imagery is limited to charts, diagrams and typography by design, since the
  sample declares `diagram-only`. Enable a provider in `image-sources.json` to
  reproduce an image-led variant.
- Slide 5 uses clearly-labelled *illustrative* data. It is marked `confidence:
  low` in the evidence ledger and must be replaced before any real use.
- `references-slide-*.json`, `wireframes-*.pptx` and `tokens.json` are generated;
  `build.py` recreates them, and binaries stay out of version control.
- If a viewer holds the output PPTX open, `build.py` writes
  `golden-ai-hallucination-rebuild.pptx` instead of failing.
